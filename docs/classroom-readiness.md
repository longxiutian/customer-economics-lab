Use separate interactive, analysis and debrief worker lanes. Only checkpoint transitions 13→14 (fresh statistical fit) and 17→18 (report) use the analysis lane. The instructor configures the lane limits; the broker enforces them atomically. Never run 45 multithreaded fits merely because 45 students arrived. ## Admission and student progress

All student jobs, workers and the router share the same work expiry, at least 30 seconds before the controller's shutdown deadline. The prepared controller ends 120 seconds before the Slurm limit. The router closes new admission 165 seconds before work expiry but retains transport for already dispatched work. Pool cleanup begins at work expiry; it does not subtract that cleanup reserve twice. These deadlines are recorded from the actual allocation before activating the broker.

The broker accepts at most its configured queue capacity, keeps one active job per authenticated owner, and binds an idempotency key to its original payload. A claim retry returns the same worker's unsettled job. Concurrent admission and claims use conditional SQL and uniqueness constraints. Broker order uses the insertion row sequence, not wall-clock timestamps. Expired unstarted jobs are marked explicitly; uncertain dispatched jobs are never blindly repeated. A late result from its original worker can settle an interrupted job because that job is never reassigned.

CPU queue position is a current FIFO rank within the requested lane. The model router ranks eligible students by its least-recently-served rule, with FIFO within a student's work. Requests blocked behind that same student's unsettled work have no rank. Model snapshots preserve their original timestamp through the worker heartbeat; stale progress is visibly labeled. A model queue rank can increase when fairness admits a newly active student.

Distinguish an ordinary queue from service interruption and an unsettled earlier request. The private progress page reports current worker/model availability without revealing prompts or peers. A request blocked behind its owner's ambiguous call has no eligible queue position; do not advance that learner through unavailable interpretations. Preserve the original request and unknown usage while other learners continue within the remaining verified capacity. A completed report does not turn an unavailable interpretation into a successful rehearsal.

Sample the local clock after reading each worker or model status file. A producer can publish between the supervisor's loop-start timestamp and its status read; comparing that newer receipt to the earlier clock creates a false future-timestamp rejection. Preserve the existing staleness, identity, capacity and expiry checks. Any cross-host clock allowance belongs in the operator's measured, tested transport contract; it must be small, explicit, and must not extend stale-readiness or allocation deadlines. Preserve failures and fix the next release rather than modifying an already frozen execution copy.

Return the workspace revision, checkpoint, packet and job states from one database read transaction. A worker may finish while a status response is being assembled; never combine its completed job with the previous checkpoint or retain it as an active job. The private progress route uses the same snapshot rule. Test completion during the read, in addition to queue-rank consistency, and reconcile all saved workspaces after a burst test.

BlueChip returns a private live-progress URL. The page refreshes about every three seconds with jitter and backoff, pauses polling while hidden, and shows the last update during connection loss. Its bearer is run-scoped, read-only, kept in the URL fragment then removed from browser history, and sent only in an authorization header. It exposes no prompts, peers or downloads. It expires within 30 minutes and the lab window; authenticated BlueChip status renews it. Native chat push is not presumed: use `check progress` to fetch a finished checkpoint in BlueChip. Do not send another start to replace pending work.

## Durable completion and debrief

The CPU pool and router share one allocated node; their SQLite ledgers stay on node-local storage and use the SQLite backup API for durable Hickory snapshots. All analysis workers attest the same session and Hickory workspace-store ID. Windows review workers attest a separate store ID. The broker rejects mismatched stores, sessions, releases and worker identities. Its assigned debrief job supplies a frozen, redacted evidence packet and existing artifact references; Windows never needs to mount the student analysis workspace or send its metered-review credential to Longleaf.

Before generation, the provider child counts the exact templated request through the private vLLM tokenizer route. Failed preparation or token-budget checks settle as undispatched. A fully received HTTP rejection settles without retry. An interrupted generation remains uncertain and holds its slot until operator reconciliation; an elapsed timer or an unverified idle metric is not proof that the GPU stopped.

The worker saves calculation receipts before delivery. Artifact bytes are hashed, uploaded, and registered before the broker accepts a completed result. Transport failures preserve the original local receipt for redelivery. An interrupted lease does not authorize another fit. Telemetry export uses a durable outbox; an export outage cannot turn a completed model response into an ambiguous outcome.

After the report validates, a separate debrief job imports completed receipts, freezes only this learner's evidence, and calls the instructor's protected metered review service at high effort. The MCP owns model selection; the returned model and token usage are recorded. A dispatch-intent receipt precedes the call. Lost or invalid responses remain pending for operator reconciliation, with the report intact. A complete provider receipt may be rendered again without another model call. Feedback must cite owned evidence and exact quotes. HTML and PDF copies are hashed and bound to the current report and saved judgments. A changed report or judgment invalidates that debrief's completion marker.

`validation.report_complete` describes the main report. `validation.workflow_complete` additionally requires the reviewed personal debrief. Student-visible downloads use expiring run/artifact-scoped links. Personal debrief generation is instructor usage, separate from recorded learner Nemotron usage. Native BlueChip chat tokens remain unknown, not zero. This workflow delivers private downloads; it does not send email or Canvas messages.

## Reproducibility and acceptance

Delivery recovery checks the original authenticated job status, then resends saved artifacts and the saved result only when needed. It never repeats computation. A committed completion with a lost acknowledgment is detected before reupload. Required report/debrief downloads must exist before the broker accepts the associated completion flags. Display-only progress-write failures leave an old timestamp rather than failing the calculation.

Freeze one analytical release after source tests. Keep the frozen code, `uv.lock`, Node lockfile, input hashes, broker commit, agent prompt, resource profile and expiry in the deployment receipt. Preserve old runs when activating a new release/window. Router SQLite and telemetry belong on local native storage, not NFS/SMB; use SQLite's backup API for durable copies. Student workspaces and artifacts remain isolated. No visible terminal windows; Windows uses the maintained Job Object launcher, and Linux uses the bounded allocation plus owned process groups.
